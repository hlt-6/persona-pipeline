# Novalcard 事件机制研读（Starstacker，2026-10-23）

对象：ghostboyfriends/sillytavern-Novalcard v5.6（index.html 单文件，约 129k 字符）
目的：看它"用剧情塑造人物"的做法，为我们流水线的事件证据轨取经。

## 它处理剧情的三件东西

### 1. 事件导向模板（EVENT_TPL）—— 人设卡的字段设计
五套模板之一，专为"经历塑造型"角色。与默认模板的差别在三个字段：

- `key_events`：人生关键事件，按时间顺序，**每条是三元组：时间 / 事件 / 影响**
  ——"影响"这一格就是剧情→性格的桥，是全模板最值钱的设计。
- `turning_points`：塑造其性格/命运的转折点，注明"原文里真实发生的，避免空泛"。
- `personality.core_traits`：格式强制 `特质: 原文中的具体体现（哪一段/哪件事表现出来）`
  ——用字段格式逼模型把每个性格结论挂到一件具体的事上（散文级证据锚定）。

另外两个克制设计：`hidden_motives` 注明"仅在原文有暗示时写，无则留空"（反编造）；
`speech_style` 只占一个字段 —— 它的重心在经历不在台词，和我们正好互补。

### 2. 剧情分段总结 —— 产出进世界书，不进人设卡
- 按顺序切大块（4–5 万字/段），逐段让模型按"阶段/副本"切分总结；
- 每段一条世界书条目：title + keys（触发词）+ content（**≥300 字，必须含
  出场角色、前因后果、重要道具、时间线，"不可遗漏任何剧情和伏笔"**）；
- 绿灯（关键词触发）注入 —— 剧情是"背景知识"，聊天时按需唤起，不占常驻上下文。
- 断点续跑、失败跳段、即时落盘，工程完成度不错。

### 3. 自检 —— 模型对照原文的软校验
- 对每张卡/条目，用关键词从原文检索相关段落作参考（搜不到则全书抽样兜底）；
- 校对提示词查四类错：① OOC；② 经历互串（把别人的经历安过来）；
  ③ 事实错误/张冠李戴/时间线错乱；④ 编造原文没有的设定；
- 输出问题日志 + 修正稿。理念对，但执行是"模型看模型"，没有硬校验。

## 它没做的（正是我们的长处）
- 无逐字校验：key_events 的"事件/影响"全是模型转述，写错、串线只能靠自检软查；
- 无编号/定位：core_traits 说"哪一段/哪件事"，但不给章节段落编号，无法机器回溯；
- 采样喂料：生成角色卡走"相关段落采样"，不是全书逐章覆盖，长篇后段的事件可能漏；
- 剧情与人设是两条线：剧情分段进了世界书，事件模板进了卡，但没有机制保证
  卡里的 key_events 与剧情条目互相一致。

## 嫁接方案（给我们的事件轨）
1. **字段直接借**：事件轨的单条结构就用 `章节 + 时间线位置 / 事件 / 她的选择 / 代价 / 影响`
   ——在他的三元组上加"选择"和"代价"两格，因为塑造性格的是抉择不是遭遇本身。
2. **纪律换我们的**：事件不许模型自由转述后直接入账；沿用编号答题：
   工具按章切段编号，模型只回"哪些段构成关键事件 + 事件类型码"，
   事件文本由工具回填原文段落，影響/推论单独成字段并标注"推论"，
   与"原文事实"分栏 —— 推论可以错，事实不许错。
3. **core_traits 的格式借到 02**：分析器输出性格结论时强制
   `结论 ← 事件编号/台词编号` 双锚，事件锚优先（回应复审 P2-1：情感/价值观靠事件，
   台词只作旁证）。
4. **剧情分段的去向借它的**：全书剧情大纲做成 lorebook 条目（绿灯触发），
   不进 system_prompt —— 和我们已定的上下文预算原则一致；
   但条目内容必须由已校验的事件轨汇总生成，不许模型另写一份造成双账。
5. 自检的四类错误清单（尤其"经历互串"）可以直接进我们的探针题库。

一句话：他的事件模板值得偷师，自检清单值得抄，
但实现路线走我们的 —— 编号、回填、校验、双账合一。
