# 低 token 抽取协议（编号答题）

原来的做法是把整章原文 + 提示词发过去，让模型吐回一个完整 JSON 数组，
每条都带 `line` 全文。贵的地方不在输入，在**输出**：43 条台词 × 每条 ~100 字
（台词原样 + evidence 一句话）＝ 四千多字，而且每个字都要模型自己生成。

改成一件事就够了：**台词原文不让模型生成，让它只回编号。**

```
[1]“（原文台词，此处省略）”
[2]“（原文台词，此处省略）”
```

（示例中的台词原文已按版权要求略去；实际包内是完整原文。）

编号由工具在原文里原位插入，模型回答时只写：

```json
{"a":[[1,"杨思思","M"],[2,"米高","T"]],"x":[非台词的编号]}
```

台词原文由 `apply_answers.py` 从章节里机械取出。**模型从头到尾没有机会抄错或编造一句台词**——
这不是靠提示词约束，是结构上做不到。

## 实测（第 324、330、339、630、357、610 章，168 条台词）

| 方案 | 输入 | 输出 | 合计 | 折算 token |
|---|---|---|---|---|
| 原方案（整章 + 全量 JSON） | 20,706 字 | 23,929 字 | 44,635 字 | ≈ 29,800 |
| 答题包（编号 + 只回编号） | 24,684 字 | 3,107 字 | 27,791 字 | ≈ 18,500 |

- **输出降低 87.0%，总量降低 37.7%**
- 输入增加 3,978 字（编号插入原文 + 口径说明），换来输出少 20,822 字
- 输出单价通常高于输入，实际省的钱比 37.7% 更多
- 按六章均值外推全书 771 章：**约 382 万 → 238 万 token**（1.5 字/token 粗估）

> 四章口径时总量降 43.1%，六章变成 37.7%。原因不是协议变差，而是**包头补了约 180 字的
> 口径说明**（见下节），而 357、610 两章本身较短（2,708 / 2,215 字），固定开销占比被抬高。
> 这部分输入换来的是"笑声被误排除"这类系统性错误的消失，值得。

## 包头必须写死的口径（丢了就会系统性出错）

答题包的说明不是客套话，少写一条就会整类出错。2026-10-22 的自动跑实测里，330 章两处
「咯咯」被模型判成非台词放进 `x`，根因就是旧版包头把 dsh 提示词第 22 行的口径弄丢了：

| 口径 | 为什么必须有 |
|---|---|
| 笑声与语气词（咯咯、嘿嘿、呵呵、嗯、唉、啊、噢）也算台词，一律进 `a` | 丢了这一条，模型会把笑声当噪音清掉，台词召回掉 1.6% |
| `x` 只放**根本不是说话内容**的片段（店名、地名、品牌、术语、书名、被引用的绰号） | 不写清楚，`x` 会变成"拿不准就丢这儿"的垃圾桶 |
| 齐声/群体发言可用集体名（如「三个小孩」），不算未知 | 否则模型会为了守"填未知"的规矩，把齐声台词判成无法归属 |
| 每个编号必须出现且只出现一次 | 这是编号级对账的前提，漏一个会被判失败 |

## 用法

```bash
# 1. 生成答题包（免费，本地跑）
python runner/rulepass.py --batch 324,330,339,630,357,610 --packet

# 2. 把 novels/fenghua/packets/ch330.packet.md 整段粘给 dsh（或任何模型）

# 3. 它回一段 JSON，存成 novels/fenghua/answers/ch330.json

# 4. 回填 + 核验 + 编号对账（免费）
python runner/apply_answers.py --chapter 330 --answers novels/fenghua/answers/ch330.json
```

第 4 步会跑和以前完全一样的核验：逐字比对、说话人出场校验、别名归一、引号覆盖率，
外加一层**编号级对账**。

## 这个协议顺带解决的两个老问题

**1. 重复台词无法按文本匹配。** 330 章有两个“咯咯”、339 章有两个“我知道。”，
用台词文本去对齐会撞车——早期用「文本→编号」的字典生成答卷时，后一个把前一个覆盖了，
结果一个编号被答两次、另一个从未被回答。按编号回答不存在这个问题，
因为编号来自原文位置，与文本无关。

**2. 漏检可数，而且必须落进报告。** 答题包里编号是工具给的，理论上少回一个编号就能发现。
但早期只有一行控制台警告，没写进报告，审计照样报 100%——这就是复审指出的静默丢句通道。
现在 `apply_answers.py` 做编号级对账（重复/漏号/越界/既答又排除），
**不闭合直接把判定改为不通过**，并把对账表写进 `out/ch*.report.md`。
`tamper_test.py` 里的「同文不同编号」用例专门守这条：文本覆盖率 100%、编号对账 ❌。

## 试过但失败的：规则预判层

本来想用规则把“某某说道”这类明确标记先判掉，只把剩下的模糊条目送模型。
实测结果否掉了这个想法：

| 规则 | 判定条数 | 正确 | 精度 |
|---|---|---|---|
| R1 同段说话动词标记 | 13 | 11 | 84.6% |
| R3 双人轮次交替 | 28 | 13 | 46.4% |

- R1 精度够，但只覆盖 13/123（10%），省下的量抵不上维护成本
- R3 精度 46%，**比抛硬币还差**——这个小说里经常连着两句同一个人说、
  或者中间插一段旁人动作，机械交替必然判错
- 结论：中文小说的说话人归属做不到“规则解决 80%，模型兜底 20%”，
  只能整体交给模型，从**输出格式**上省钱而不是从任务量上省钱

代码留在 `runner/rulepass.py`，`--eval` 可以随时重跑这组数字。
