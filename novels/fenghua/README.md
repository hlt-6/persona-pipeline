# 我在风花雪月里等你 · 台词提取（dsh 提示词 v1 + 证据核验）

用 `dsh提取提示词.md` 的规则，对第 324、330、339、630、357、610 六章做逐句台词抽取与归属，
并用改造过的工具对结果做机器核验。**168 条台词，全部逐字命中原文，逐号对账闭合，覆盖率 100%。**

## 先说清楚谁做了什么

| 环节 | 谁做的 |
|---|---|
| 按章切分原文、枚举每章所有引号片段 | 工具（`split_chapters.py` / `extract.py spans`） |
| **逐条判读台词、判断说话人、写判断依据** | **本会话的模型人工完成**，落盘在 `benchmark/ch*.json` |
| 逐字核验、说话人出场校验、别名归一、覆盖率审计 | 工具（`extract.py run`） |
| 编号级对账（重复/漏号/越界） | 工具（`apply_answers.py`，报告里落表） |
| 反证测试（11 类注入错误） | 工具（`tamper_test.py`） |
| 合并语料、按角色拆分 | 工具（`merge_lines.py`） |

**没有用 dsh / DS 平台跑过一次。** 本机没有 `dsh` 可执行文件，也没有 `DS_API_KEY`，
`run --chapter N` 的在线分支（真调模型）本次**未被执行**。

另外要说明一个方法上的偏差：抽取前我先用 `spans` 枚举了每章的引号清单
（324/330/339/630/357/610 = 26/42/32/31/19/30 个），再逐条填写，相当于**开卷**。
所以 100% 覆盖率证明的是「这份结果既没有漏、也没有编」，**不能**证明「模型自己跑能到这个覆盖率」。
这六章的正确定位是**基准答案卷**，用来量模型的实际召回——而不是工具能力的演示。

## 版权边界：哪些进了仓库，哪些没有

这本书是版权作品，仓库里**不留任何原著正文**。含正文的文件全部被
`novels/fenghua/.gitignore` 挡在版本库外，只在本地工作副本中存在：

| 本地文件 | 是否入库 | 原因 |
|---|---|---|
| `source.txt` | ❌ | 小说全文（6.2 MB） |
| `extract-prompt.md` | ❌ | 抽取提示词，使用者工作文件 |
| `chapters/` | ❌ | 整章原文 |
| `packets/` | ❌ | 整章原文 + 编号 |
| `out/` | ❌ | 结果与报告，含逐条台词原文 |
| `benchmark/` | ❌ | 完整答案卷，逐字引用原文约 1.2 万字 |
| `benchmark-public/` | ✅ | **脱敏答案卷**：只留编号、说话人、依据码、段落指针，0 字原文 |
| `answers/` | ✅ | 只有 `[编号, 说话人, 依据码]`，不含台词 |
| `roster.json` | ✅ | 人名与出现次数（统计结果，不是原文） |

`runner/redact_bench.py` 负责生成 `benchmark-public/`：它把 `evidence` 里引用的原文
片段替换为 `〔原文〕`、`line` 整条删掉，但**依据码在剥引号之前算好并存下来**，否则
"说道/标记"这类关键字会跟着引文一起被带走，`M` 就退化成 `T`。

脱敏卷仍能完整驱动评测，只要你有原著的合法副本：

```bash
python runner/bench_to_answers.py --from-public --chapters 330
python runner/apply_answers.py --chapter 330 --answers novels/fenghua/answers/ch330.json
```

两条路径（`benchmark` 按文本对齐 / `benchmark-public` 按编号）产出的答卷**逐字节一致**，
已实测校验。核验脚本所需的原文只在运行时从你本地的 `source.txt` 读取，从不进仓库。

## 怎么跑

```bash
cd persona-pipeline

# 1. 环境自检（检查小说/提示词/章节数/API key）
python runner/extract.py doctor

# 2. 切章 + 看某章有多少个引号（提取的"分母"）
python runner/split_chapters.py --chapters 357,610
python runner/extract.py spans --chapter 610

# 3. 抽取 + 核验
#    a) 有 API key 时，直接让模型抽：
python runner/extract.py run --chapter 330
#    b) 没有 key 时，用已生成的结果做离线核验：
python runner/extract.py run --chapter 330 --result novels/fenghua/benchmark/ch330.json

# 4. 批量
python runner/extract.py batch --chapters 324,330,339,630,357,610 \
    --result-dir novels/fenghua/benchmark

# 5. 合并成语料
python runner/merge_lines.py --chapters 324,330,339,630,357,610
```

### 低 token 路径（推荐，尤其是要跑全书时）

```bash
# 生成编号答题包：台词由工具编号，模型只回 [编号,说话人,依据码]
python runner/rulepass.py --batch 324,330,339,630,357,610 --packet

# 把 packets/ch330.packet.md 整段粘给 dsh，得到 JSON 存到 answers/ch330.json

# 回填 + 核验 + 编号对账（台词原文由工具从章节取，模型碰不到）
python runner/apply_answers.py --chapter 330 --answers novels/fenghua/answers/ch330.json
```

实测（168 条台词口径）：**输出 token 降低 87.0%，总 token 降低 37.7%**。
细节与失败尝试见 [`packet-protocol.md`](packet-protocol.md)。

### 自检与反证

```bash
# 用 benchmark 反向生成一份"答卷"，跑通回填→核验→对账闭环（模拟用，不是模型输出）
python runner/bench_to_answers.py --chapters 324,330,339,630,357,610

# 往正确结果里注入 11 类错误，确认每一类都被拦住
python runner/tamper_test.py --chapter 330
```

## 对提示词的改动（按提示词要求逐条记录）

提示词里说"你可以改的地方（改了请记下来告诉我）"，以下是全部改动，**字段语义一个没动**，
`speaker` / `evidence` / `confidence` 三字段原样保留，所以能和人工审计对答案。

| # | 改了什么 | 为什么 | 影响 |
|---|---|---|---|
| 1 | 输出从裸数组改为 `{"lines": [...], "excluded": [...]}` | DeepSeek 的 `json_object` 模式要求顶层是对象；`excluded` 让"排除项"也进入审计视野 | 只加了一层包装，`lines` 内元素结构不变 |
| 2 | 新增硬约束：`line` 必须逐字出现在本章原文 | 这是唯一能证伪"编造/改写台词"的检查，只靠提示词做不到 | 改写一个字就会被判 FATAL |
| 3 | 新增硬约束：`speaker` 必须在本章有依据 | 防编造人物；第一人称叙述者豁免 | 叙述者本名可整章不出现 |
| 4 | 新增：用别名（四哥／杨如画／思思）填 speaker 会告警 | 别名表要求用本名，但原文里"我四哥"在 610 章出现 5 次，模型容易照抄 | 已归一到"杨思思" |
| 5 | `speaker=未知` 必须配 `confidence=low`，且 `low` 必须写 `note` | 原提示词只说"宁可标未知"，没有可检查的形式 | 630 章"早生贵子"走通了这条路径 |
| 6 | 前后窗口 3-5 句**未改** | — | — |
| 7 | `confidence` 判定标准**未改** | — | 但取值限死 high/low，`medium` 会被判非法 |
| 8 | 新增编号级对账（答卷必须逐号闭合） | 文本级覆盖率会被"同文不同编号"掩盖，详见下节 | 漏号/重号一律判不通过 |

## 核验能力自测（11 类注入错误）

`runner/tamper_test.py` 对第 330 章的正确答案逐条注入错误，**11/11 全部拦住**，存档 `out/_tamper-test.report.md`：

| 用例 | 预期 | 实际 |
|---|---|---|
| 基准（未注入） | 通过 | ✅ 0 致命 0 警告 |
| 改写台词 2 字 | 致命 | ✅ 1 致命，覆盖率掉到 98% |
| 换成本章未出场的人（陈进） | 致命 | ✅ 1 致命 |
| 说话人填别名（四哥） | 警告 | ✅ 1 警告 |
| 抽掉判断依据 | 致命 | ✅ 1 致命 |
| 置信度填非法值（medium） | 警告 | ✅ 1 警告 |
| 删掉一条答案（漏号） | 编号不闭合 | ✅ ❌ 检出 |
| 同一个编号答两次 | 编号不闭合 | ✅ ❌ 检出 |
| 排除一个不存在的编号 | 编号不闭合 | ✅ ❌ 检出 |
| 同一编号既作答又排除 | 编号不闭合 | ✅ ❌ 检出 |
| **同文不同编号**（29/30 都答成 29） | 编号不闭合 | ✅ **文本覆盖仍 100%，只有编号对账抓到** |

最后一行是**这次返包复审发现的静默丢句通道**：330 章两处「咯咯」、339 章两处「我知道。」，
把两条都答成同一个编号，文本多重集看起来仍然完整，审计会报 100%。
现在两条都查：文本级改为一对一消耗匹配，编号级逐号核对并写进报告。

## 跑这一遍发现的几件事

**1. 主角的名字几乎不出现。** "米高"在 324、330、630、610 四章正文里出现 **0 次**，339 章
只出现 1 次（全章唯一一次是陈进说话时提到他的名字）。第一人称小说里要按"名字必须出现"
校验，会把主角的台词全部误判成编造。这是提示词没考虑到的情况。

**2. 630 章与 610 章是"缺席的在场"。** 630 章杨思思零台词却被提及 6 次；610 章她同样零台词，
"我四哥"出现 5 次、"四哥"共 8 次，全部出自周三三之口，而米高在整章里只叫"杨思思"（5 次）。
同一个人，弟弟嘴里是"我四哥"，旧情人口里是全名——这是 persona Layer 4（对人差异）最硬的证据，
但只统计"谁说了什么"的流水线会把整章丢掉。**建议后续增加 mentions 轨道**（谁、用哪个称呼、
什么语境），目前尚未实现。

**3. 357 章是改口分水岭。** 全章"杨思思"出现 17 次、"杨如画"6 次：对话里仍叫旧名，
旁白已经改口（两处叙述都在说要和过去那个任性的杨思思告别）。
本章还有 4 处引号不是台词——`杨如画`（人名被引号括起）、`古城保护管理局`/`古城管理保护局`
（机构名，原文两种写法并存）、`山水间`（楼盘名）。这四类正好是"x 该放什么"的典型样本。

**4. 610 章的「吁」暴露了口径冲突。** 原文"我『吁』出一口气"里的单字引号，
按旧逻辑会被报"疑似源文件引号错误"，但它是拟声词、属于发声内容。现在
`LAUGH_RE` 收录语气词/拟声词后不再误报，这一条也按"语气词算台词"计入米高。
